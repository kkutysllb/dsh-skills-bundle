## 背景

与 dsh-kylin-images v0.1.2 同款问题：麒麟（QiLin）与 DSH 双引擎升级后，
应用内「语言」设置升级为宿主托管偏好（LocaleRuntime，账户菜单切换、存宿主
设置、跨浏览器共享；`navigator.language` 只是无显式选择时的临时兜底）。
本插件 client.js 仍以 `navigator.language` 判定双语——两个信号源分叉后，
设置页「可选技能」分区在中文界面下钉死英文。

## 修复

- `exports.inject` 补 `locale` 声明；`package.json` 的 dsh/qilin
  client.inject 元数据补 `@deepseek-ai/dsh-client-locale`（此前两处都未
  声明，`ctx.locale` 不可用）；
- `apply()` 头部：`ctx.locale.register('kcoderSkills', { zh, en })` 注册
  命名空间字典（词典本就扁平，无需摊平），`t = ctx.locale.bind(NS)` ——
  译函调用时读当前应用语言，账户菜单切语言即时生效；
- 设置分区 nav 行 `label` 由字符串改 **thunk**（`label: function () {
  return t("nav"); }`）——宿主每次投影重读，语言切换后导航行跟随，无需
  重注册；
- 老引擎无 `ctx.locale` 面时自动落回原 navigator 兜底译函，行为与 1.1.1
  完全一致。
