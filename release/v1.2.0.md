## 背景

Office 文档处理与「方法论技能包」的定位不符：这批技能是文件格式工具而非
工程方法论，且是包内体积大头（docx/pptx/xlsx 各自带整套 OOXML schemas
与 validators）。宿主侧已有专职的 office 技能套件（office / office-docx /
office-pptx / office-xlsx / office-export-pdf / office-render /
office-recalculate）承接同类能力，随包重复分发只增目录税。

## 变更

- 删除 `skills/optional/docx`、`skills/optional/pptx`、`skills/optional/xlsx`、
  `skills/optional/pdf` 四个技能目录（含各自 scripts/、schemas/ 载荷）；
- `skills/manifest.json` 的 optional 批经 `pnpm gen:manifest` 重扫：40 → **36 项**
  （core 31 项不变，脚本从不改写 core 批）；
- `scripts/selftest.mjs` 夹具由 xlsx/pptx 换为存活的 slidev/todo（断言计数同步）；
- `README.md` 可选技能计数 40 → 36；
- 设置页「可选技能」分区、fenced API、启用集持久化等机制零改动。

## 兼容性

- 四个退役技能均为 optional 批（**默认不注册**）：未启用过的用户升级后
  零感知；仅在设置页显式启用过它们的用户升级后不再可启用。
- 持久化状态文件（`kcoder-skills.json`）里残留的退役技能名会被
  entry.js 的 manifest 白名单静默过滤，无报错、不阻塞其余启用集恢复。
- 其余 36 个可选技能与 31 个核心技能不受影响。
